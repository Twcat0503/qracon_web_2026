# 01 — 設計系統與主視覺概念

> **狀態（2026-07-28 更新）**
> 已定案：主視覺方案 A 雙狹縫干涉、色彩方向「相位雙色」。
> 未定案：年度主題（交主辦團隊）、實際色票色值、字型最終組合。

## 設計原則（先定原則，再選方案）

1. **量子的視覺語言是「機率」，不是「科幻」**
   量子科技的網站最常見的失敗，是套用一堆藍色發光電路、機械手臂、賽博龐克格柵——
   那是 1990 年代對「未來」的想像，不是量子。量子真正的特徵是**疊加、機率分布、
   干涉、糾纏、觀測即坍縮**。視覺應該表達「同時是又不是」「多重可能性」「觀測改變結果」，
   而不是「科技感」。

2. **互動要有物理意義**
   滑鼠移動不該只是視差。若首屏是干涉圖樣，游標就是波源；若是 Bloch 球，
   拖曳就是旋轉量子態。互動本身即是科普——**這是 QRACON 作為教育型年會的網站該有的東西**，
   也是與 SITCON 拉開差異的關鍵。

3. **資訊優先於效果**
   3D 與動效在資訊之下、之後。首屏必須三秒內回答「什麼活動、什麼時候、在哪、怎麼報名」。

4. **學生感，不是企業感**
   這是學生主導的年會。可以有玩心、有粗糙的手感、有實驗性；
   不需要看起來像 IBM Quantum 或 Google Quantum AI 的公司網站。

## 主視覺方案評估與定案

### 方案 A — 雙狹縫干涉（Interference）

全螢幕 GLSL shader 產生的干涉條紋。游標即波源，移動時條紋隨之重組；
捲動時「觀測」發生，波紋坍縮成粒子點陣，議程資訊從點陣中浮現。

- **量子概念**：波粒二象性、觀測效應——量子力學最有名也最好懂的實驗。
- **技術**：純 shader，**無需 3D 模型**，檔案極小、效能最好。Three.js 只當 GL 載體。
- **視覺調性**：極簡、單色或雙色、大量負空間、科學感而非科幻感。
- **難度**：中（shader 調參需要時間，但無資產製作成本）。
- **風險**：純抽象，若處理不好會顯得單薄；需要強字體排印撐場。

### 方案 B — Bloch 球（Superposition）

可拖曳的 3D Bloch 球，球面上的態向量隨互動移動；捲動時態向量在 |0⟩ 與 |1⟩ 之間
旋轉，對應頁面章節切換。旁邊即時顯示對應的量子態表示式。

- **量子概念**：疊加態——量子計算的核心，且能真正教會訪客一件事。
- **技術**：Three.js 幾何 + 線框，程序化生成，無需 Blender 資產。
- **視覺調性**：教科書的優雅、精密儀器感、線條為主。
- **難度**：中低（幾何都是程序化的）。
- **風險**：Bloch 球在量子教材裡太常見，原創性最低；容易被說「就是教科書插圖」。

### 方案 C — 糾纏網格（Entanglement）

3D 空間中的節點群，節點成對糾纏——操作其中一個，配對的另一個立即同步反應
（不論距離多遠）。節點對應網站各區塊，形成導覽本身。

- **量子概念**：量子糾纏、非定域性。QRACON 2025 的承辦方名稱正是 EntangleTech，有承接感。
- **技術**：Three.js instanced mesh + 連線，可搭配 `cannon-es` 讓節點有物理慣性。
- **視覺調性**：有機、網絡狀、深度層次豐富。
- **難度**：高（節點數與效能的平衡、行動裝置退化策略）。
- **風險**：最容易掉進「粒子連線特效」這個被用爛的視覺陳腔（particles.js 那種）。
  要做必須在美術上做出明確區隔。

### ✅ 定案：方案 A 雙狹縫干涉（2026-07-28）

首屏採方案 A。方案 B（Bloch 球）保留為「關於量子計算」科普區塊的互動教具，
屬 P4 加分項，非必做。方案 C 捨棄。

#### 實作重點

- 純 GLSL fragment shader，**不載入任何 3D 模型**。Three.js 僅作為 GL context 與
  uniform 管理的載體；若最終發現 Three.js 過重，可改用裸 WebGL2 —— 此決定延後到實作時
  依 bundle 實測決定，見 `03-tech-stack.md` 的 250 KB 預算。
- 干涉場由兩個波源疊加。基礎波源固定，第三個波源跟隨游標（桌機）或
  觸控點（行動裝置）；無指標輸入時波源做緩慢自走，畫面不得靜止死板。
- **捲動即觀測**：捲動進度驅動一個 `uCollapse` uniform（0→1）。
  0 為連續波場、1 為離散粒子點陣，中間為兩者的混合。這條 uniform 是整個
  首屏敘事的主軸，其他動效都應與它同步，不要各自為政。
- Fallback（WebGL 不可用 / reduced-motion / 低階裝置）：輸出一張**設計過的**
  靜態干涉圖，不是 canvas 截圖。此圖同時作為 OG image 的基底。

## 年度主題（Theme）發想

2025 的「Planck 100」錨定百年紀念，2026 需要新錨點。三個方向：

| 方向             | 概念                                   | 一句標語草稿                         |
| ---------------- | -------------------------------------- | ------------------------------------ |
| **南向／擴散**   | 首次移師南部院區，量子知識向南擴散     | 「量子南向」／把疊加態帶到北緯 23 度 |
| **觀測／參與**   | 觀測者改變系統——學生參與改變領域的未來 | 「觀測即參與」Observe to Collapse    |
| **疊加／可能性** | 學生的職涯與量子產業都處於疊加態       | 「所有可能性都還在」Before Collapse  |

**狀態（2026-07-28）：交由主辦團隊決定，網站端不自行定案。**

在主題回覆前，網站以**佔位文案**往下做，並確保主題落地時只需改動少數幾處：

- 主標語、副標語一律放 `src/data/site.ts` 的 `theme` 欄位，
  **不得散落在各 `.astro` 樣板中**。主題定案時只改這一個檔。
- 佔位文案用明確可搜尋的標記（如 `TODO(theme):`），不要用看起來像成品的假文案，
  以免誤上線。
- 主視覺與互動邏輯**不依賴**主題文字，因此主題延後不阻擋 P2/P3 開發。

若主辦團隊需要提案參考，上表三個方向可直接轉交；工程端建議「觀測／參與」，
因為它與已定案的主視覺（游標即觀測者、捲動即坍縮）能扣成同一個系統。

## ✅ 色彩：相位雙色（方向 2026-07-28、色值 2026-09-11 定案）

避開量子產業網站的預設藍紫漸層。採**兩個對立色**代表兩個相位（|0⟩ 與 |1⟩），
中間態為兩色的連續混合。

### 為什麼這與方案 A 是同一件事

干涉條紋的明暗，物理上就是兩束波的**相位差**。因此：

- 建設性干涉（同相）→ 色 A
- 破壞性干涉（反相）→ 色 B
- 相位差介於兩者 → 兩色在感知均勻色彩空間中的連續插值

配色不是套在主視覺上的裝飾，而是主視覺的**物理結果**。整站的色彩系統即由此推導：
主色 A、主色 B、以及兩者混合出的中間階梯，就是全部的色相來源。
**不要引入第三個無關色相**——那會讓這套邏輯失效。

### 色值（使用者 2026-09-11 拍板）

兩個相位直接取自主視覺 `art/QRACON2026主視覺形象圖.jpg`，**純灰階、全站零色相**：

- 相位 A＝墨 `#000`：印刷、線條、反白色帶。
- 相位 B＝紙 `#D9D9D9`：底色、車票卡紙。
- 白 `#FFF`：點亮的月台牌、翻牌面、車票本身。
- 中間階梯是墨與紙的混合，定義在 `src/styles/tokens.css`，每個灰階都註明對比度；
  shader 在線性空間混色（紙在線性空間是 0.6938）。

原本「兩個高彩度對立色」的候選色票流程因此不再需要；色盲可辨性由純明度差自然滿足，
場次狀態一律用文字標示，不靠灰階深淺區分。

## 字型（提案，未定）

必須是**可商用授權**的開源字型（研討會網站無預算買商業授權）。

| 用途               | 候選                                    | 備註                                 |
| ------------------ | --------------------------------------- | ------------------------------------ |
| 中文標題           | **台北黑體 Taipei Sans TC**             | 台灣在地開源，字面方正有力，適合大標 |
| 中文標題（替代）   | 芫荽 Iansui / 源樣黑體 GenYoGothic      | —                                    |
| 中文內文           | **思源黑體 Noto Sans TC**               | 字重齊全、螢幕可讀性最穩             |
| 英數標題           | 待定，需與中文標題配對                  | —                                    |
| 數據／程式碼／時間 | **JetBrains Mono** 或 **IBM Plex Mono** | 議程時刻表、量子態符號用等寬         |

**技術要求**：中文字型檔極大，**必須做 subset**（依實際用字產生子集），
並用 `font-display: swap` + preload 關鍵字重。未 subset 直接上傳中文字型會炸掉 LCP。

量子態符號（|0⟩、|1⟩、⟨ψ|）需確認選用字型有涵蓋這些 Unicode 字元，
否則需另指定 fallback 或改用 SVG。

## Design Token 規範

定案後，所有 token 定義於 `src/styles/tokens.css`，**這是唯一來源**。

```text
--color-*      顏色
--font-*       字族
--text-*       字級（用 clamp() 做流體排版）
--space-*      間距（8px 基準的等比級數）
--radius-*     圓角
--ease-*       緩動曲線
--dur-*        動畫時長
--z-*          層級
```

元件中禁止出現裸色碼、裸 px 間距、裸 `cubic-bezier()`。

## 動效原則

- **緩動有物理感**：不用線性、不用預設 `ease`。定義 3–4 條曲線並複用。
- **進場動畫只做一次**：不要每次捲回都重播，會惱人。
- **時長克制**：介面回饋 150–250ms；區塊進場 400–600ms；主視覺敘事可長。
- **`prefers-reduced-motion: reduce` 必須真的降級**：不是縮短時間，是移除位移與視差，
  只保留不引發前庭不適的淡入。
- 各元件的觸發、時長、token 與降級方式見 **`06-motion.md`**（2026-09-12 定案並實作）。
